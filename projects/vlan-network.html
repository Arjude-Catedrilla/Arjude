Segmented VLAN Network for a Multi-Department Office

Details are generalized. Addresses, device names, department names, and the employer are intentionally left out.

Overview

I planned, configured, and documented a segmented network for an office of 50+ users, using a TP-Link Omada router and managed switch.

The problem

The office ran on the ISP-provided router and unmanaged switches. That typically means one flat network where every device shares the same space, with no way to separate departments, isolate guests, or control who can reach what.

The design

Five VLANs by role: IT admin, two departments, management, and guest. The router does the routing and is the only DHCP server. The switch uplink is a trunk, end-device ports are untagged access ports, and the management port carries the two department VLANs tagged, so managers can reach both departments without merging them.

Access control

Eleven ACL rules, processed top-down with the first match winning, so permit rules sit above deny rules. Departments are isolated from each other and from IT admin, and guests are fully isolated. Management can reach both departments. A single-device exception uses a /32 IP group, backed by a DHCP reservation so the address never changes.

Three management modes

I ran the same network in standalone, cloud, and software-controller modes and documented the tradeoffs.

Lessons learned

  • Only one DHCP server per subnet. A second one causes address conflicts and routing failures.
  • The controller’s configured IP must match its real address, or devices show as disconnected while the network keeps working.
  • /24 targets a whole subnet and /32 targets one device. Mixing them up grants far more access than intended.
  • Run ipconfig /release before /renew, or the DHCP reservation is ignored.
  • Boot the router first, then the switch.
  • Back up before any reset, and test with a ping after every single change.

Result

  • Departments and guests are now separated, with controlled access for management.
  • One DHCP server serves every VLAN, with reservations for key devices.
  • The documentation was complete enough that I rebuilt the whole configuration from it when I moved back to standalone mode.

My role

I planned the network, installed and configured the equipment, and wrote the documentation. I used an AI assistant to help work out the VLAN and ACL configuration, then tested and refined it myself.

What I would improve

A dedicated always-on controller, DHCP reservations for all key devices, and DNS filtering per VLAN.
